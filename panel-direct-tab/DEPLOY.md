# Вкладка «Директ» для панели SEO Статистики

Ставится поверх дерева панели одним скриптом, идемпотентно. Обновление — тем же способом,
что и первая установка.

```powershell
python apply_direct_tab.py --app-root <корень панели>   # где лежит app/
Restart-Service <служба панели>
```

Установщик копирует файлы `app/**`, регистрирует роутер в `app/main.py`, добавляет пункт
меню в `nav.html` и врезает ночной сбор в `app/scheduler/jobs.py`. Каждый изменяемый файл
бэкапится рядом как `*.bak-direct` — откат сводится к копированию бэкапов обратно.

Таблицы создаются при старте (`create_all`). Колонки, добавленные к уже существующим
таблицам, дописывает `ensure_direct_schema` — alembic в панели нет.

## Состав

| Файл | Что делает |

| `app/providers/yandex_direct.py` | клиент API v5: Reports и обычные сервисы |
| `app/services/direct.py` | живой просмотр |
| `app/services/direct_store.py` | запись истории и агрегаты |
| `app/services/direct_collect.py` | окно сбора, бэкфилл, ночной прогон |
| `app/services/direct_changes.py` | снапшот настроек и журнал изменений |
| `app/services/direct_accounts.py` | разведка кабинетов и привязка их к доменам |
| `app/services/metrika_resync.py` | еженедельный пересинк визитов Метрики |
| `app/db/models_direct.py` | таблицы |
| `app/api/routes_direct.py` | роутер вкладки |
| `app/templates/direct.html` | шаблон |

## Таблицы

| Таблица | Что хранит |
|---|---|
| `direct_daily` | итоги аккаунта за день |
| `direct_campaign_daily` | кампания за день |
| `direct_breakdown_daily` | срез за день: фраза / запрос / устройство / регион |
| `direct_collect_run` | журнал сборов |
| `direct_settings_snapshot` | последнее известное состояние объекта |
| `direct_change` | журнал изменений настроек |
| `direct_account` | найденные рекламные кабинеты |

Гранулярность — сутки. Upsert идемпотентен: повторный сбор дня перезаписывает строку,
это обязательно — Директ правит свежие цифры задним числом. По той же причине каждый
прогон перезабирает последние `REFETCH_DAYS` дней.

## Несколько целей рядом

Цель входит в уникальный ключ таблиц истории (`goal_key`), поэтому серии разных целей
живут рядом и переключаются на вкладке, а не затирают друг друга. Наборы задаются
текстом, по строке на набор — `Имя=ID цели`; имя становится подписью переключателя.
Несколько целей в одном наборе складываются.

Разрезы собираются только под **первый** набор: показы, клики и расход в них одни и те
же для любой цели, а копия на каждую удвоила бы самую объёмную таблицу истории.

Колонку добавляет `ensure_direct_schema`. В SQLite уникальный ключ не меняется на месте,
поэтому таблица пересобирается: новая схема, перелив строк, подмена, восстановление
индексов. Старые строки получают пустой ключ — «как собирали раньше».

## Привязка кабинетов

Один токен открывает столько кабинетов, представителем скольких является его владелец.
Перечислить их через API нельзя (`AgencyClients.get` → ошибка 54), и логин из домена не
выводится — Яндекс выдаёт логины без всякой связи с сайтом. Поэтому список логинов
копируется из интерфейса Директа и вставляется в блок «Кабинеты Директа» на вкладке;
дальше панель опрашивает каждый и **определяет домен по ссылкам объявлений**.

Привязка домен→кабинет хранится в кредах (`direct_login:<домен>`); ночной сбор идёт по
всем доменам, у которых она есть.
