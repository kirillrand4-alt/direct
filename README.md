# Статистика из Яндекс Директа через API — инструкция с нуля

Пошагово: от «у меня просто есть рекламный кабинет» до «CSV со статистикой лежит на диске и обновляется по расписанию».

Ничего предварительно знать не нужно. Все шаги — по порядку, ничего пропускать нельзя.

---

## Что получится в итоге

Скрипт, который одной командой выгружает статистику:

```bash
python direct_stats.py --date-from 2026-08-01 --date-to 2026-08-10 --out stats.csv
```

```
Отчёт готов. Строк: 143
Баллы: потрачено 12, осталось 23988 из 24000
Сохранено: stats.csv
```

## Шаг 0. Что нужно иметь до старта

- **Аккаунт Яндекса**, у которого есть доступ к рекламному кабинету Директа. Тот же логин, которым вы заходите в интерфейс Директа.
- **Python 3.9+** (проверить: `python3 --version`).
- Всё. Больше ничего не нужно, API Директа бесплатный.

> **Важно про роль аккаунта.** Если вы **рекламодатель** (ведёте свои кампании) — всё просто, идите дальше.
> Если вы **агентство** — API работает так же, но в каждом запросе придётся указывать логин клиента (заголовок `Client-Login`), а список клиентов брать через отдельный сервис `AgencyClients`. Отличия отмечены по тексту.

Ставим зависимости:

```bash
pip install -r requirements.txt
```

## Шаг 1. Регистрируем приложение в Яндекс OAuth

API Директа не пускает по логину и паролю — только по OAuth-токену. Токен выдаётся не человеку, а *приложению*. Поэтому сначала регистрируем приложение, даже если пользоваться им будете только вы один.

1. Зайдите на **https://oauth.yandex.ru/** под тем аккаунтом, у которого есть Директ.
2. Нажмите **«Создать приложение»**.
3. Заполните:

   | Поле | Что вводить |
   |---|---|
   | Название сервиса | Любое, например `Выгрузка статистики Директа` |
   | Иконка | Можно пропустить |
   | Платформы | Отметьте **«Веб-сервисы»** |
   | Redirect URI | `https://oauth.yandex.ru/verification_code` |
   | Почта для связи | Ваша рабочая почта |

4. В блоке **«Доступы»** (или «Data access») найдите через поиск **«Яндекс Директ»** и отметьте право:

   > ☑ **Использование API Яндекс Директа** (`direct:api`)

   Это единственное обязательное право. Без него токен вы получите, но Директ будет отвечать ошибкой авторизации.

5. Нажмите **«Создать приложение»**.

6. На открывшейся странице приложения запишите два значения:
   - **ClientID** — виден сразу
   - **Client secret** — под кнопкой «Показать»

   Сохраните их. `Client secret` — это пароль, его нельзя коммитить в git и пересылать в мессенджерах.

## Шаг 2. Подаём заявку на доступ к API Директа

Зарегистрированного приложения **недостаточно**. Нужна ещё отдельная заявка — это отдельная кнопка, которую все пропускают.

1. Оставаясь на странице своего приложения в Яндекс ID, найдите раздел **«API Директа»**.
2. Нажмите **«Подать заявку»** и заполните форму. Ключевой вопрос в ней — для чего приложение:
   - *для собственных рекламных кампаний* — если выгружаете свою статистику (самый частый случай, форма короткая);
   - *для внешних пользователей* — если делаете сервис, которым будут пользоваться другие.
3. Отправьте.

**Сроки:** от часа до 3 суток в рабочие дни (в пиковые периоды — до 7 дней). Заявки рассматривают в рабочие дни с 10:00 до 19:00 МСК.

**Правила:**
- На одно приложение подаётся **одна** заявка. Не плодите приложения — это замедляет рассмотрение.
- После одобрения с приложением сможет работать неограниченное число пользователей.
- Пока заявка не одобрена, боевой API отвечает ошибкой «нет доступа». Но **песочница работает сразу** — см. [раздел про песочницу](#песочница), там можно отладить код, не дожидаясь одобрения.

## Шаг 3. Получаем OAuth-токен

Есть два способа. Первый — быстрый, для разовой выгрузки. Второй — правильный, если выгрузка будет работать постоянно.

### Способ А (быстрый): токен сразу, без обмена

Откройте в браузере, подставив свой ClientID:

```
https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID
```

Подтвердите доступ — на странице покажут **access_token** вида `y0_AgAAAAB...`. Это и есть токен.

**Минус:** не будет `refresh_token`, и когда токен протухнет (обычно через год), процедуру придётся повторять руками.

### Способ Б (правильный): через код подтверждения

1. Откройте:

   ```
   https://oauth.yandex.ru/authorize?response_type=code&client_id=ВАШ_CLIENT_ID
   ```

2. Яндекс покажет **«Код подтверждения»** — короткую строку цифр. **Это ещё не токен.** Код одноразовый и живёт ~10 минут.

3. Обменяйте код на токен:

   ```bash
   curl -X POST https://oauth.yandex.ru/token \
     -d grant_type=authorization_code \
     -d code=ВАШ_КОД_ПОДТВЕРЖДЕНИЯ \
     -d client_id=ВАШ_CLIENT_ID \
     -d client_secret=ВАШ_CLIENT_SECRET
   ```

   Ответ:

   ```json
   {
     "token_type": "bearer",
     "access_token": "y0_AgAAAAB...",
     "expires_in": 31536000,
     "refresh_token": "1:xxxxxxxx..."
   }
   ```

4. **Сохраните `refresh_token`.** Когда `access_token` истечёт, новый берётся без браузера:

   ```bash
   curl -X POST https://oauth.yandex.ru/token \
     -d grant_type=refresh_token \
     -d refresh_token=ВАШ_REFRESH_TOKEN \
     -d client_id=ВАШ_CLIENT_ID \
     -d client_secret=ВАШ_CLIENT_SECRET
   ```

### Куда положить токен

Скопируйте шаблон и заполните:

```bash
cp .env.example .env
```

```ini
# .env
YANDEX_DIRECT_TOKEN=y0_AgAAAAB...
# Только для агентств — логин клиента, по которому нужна статистика:
# YANDEX_DIRECT_CLIENT_LOGIN=client-login
```

Файл `.env` уже в `.gitignore` — в репозиторий он не попадёт.

## Шаг 4. Проверяем, что всё работает

Самая дешёвая проверка — спросить у API остаток баллов. Запрос ничего не стоит и сразу покажет, в порядке ли токен и одобрена ли заявка.

```bash
curl -s -X POST https://api.direct.yandex.com/json/v5/campaigns \
  -H "Authorization: Bearer $YANDEX_DIRECT_TOKEN" \
  -H "Accept-Language: ru" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{"method":"get","params":{"SelectionCriteria":{},"FieldNames":["Id","Name"],"Page":{"Limit":3}}}'
```

- Вернулся список кампаний → **всё готово**, идите к шагу 5.
- Ошибка авторизации → токен неверный/протух, или в приложении не отмечено право `direct:api`.
- Ошибка «нет доступа к API» → заявка из шага 2 ещё не одобрена.
- `{"error": ...}` с другим текстом → смотрите [таблицу ошибок](#таблица-ошибок).

## Шаг 5. Запускаем выгрузку статистики

Статистика живёт в отдельном сервисе — **Reports**, адрес `https://api.direct.yandex.com/json/v5/reports`. Это не обычный метод `get`, а генератор отчётов: вы описываете, что хотите, а Директ отдаёт TSV.

### Самое простое — скриптом

```bash
# статистика по кампаниям за период
python direct_stats.py --date-from 2026-08-01 --date-to 2026-08-10 --out stats.csv

# по ключевым фразам
python direct_stats.py --date-from 2026-08-01 --date-to 2026-08-10 \
  --report-type CRITERIA_PERFORMANCE_REPORT --out keywords.csv

# по поисковым запросам
python direct_stats.py --date-from 2026-08-01 --date-to 2026-08-10 \
  --report-type SEARCH_QUERY_PERFORMANCE_REPORT --out queries.csv

# свой набор полей
python direct_stats.py --date-from 2026-08-01 --date-to 2026-08-10 \
  --fields Date,CampaignName,Impressions,Clicks,Cost,Ctr,AvgCpc --out custom.csv

# с конверсиями по конкретной цели Метрики
python direct_stats.py --date-from 2026-08-01 --date-to 2026-08-10 \
  --goals 123456789 \
  --fields Date,CampaignName,Clicks,Cost,Conversions,CostPerConversion --out conv.csv
```

Полный список флагов: `python direct_stats.py --help`.

### То же самое руками, через curl

Чтобы понимать, что происходит внутри:

```bash
curl -X POST https://api.direct.yandex.com/json/v5/reports \
  -H "Authorization: Bearer $YANDEX_DIRECT_TOKEN" \
  -H "Accept-Language: ru" \
  -H "Content-Type: application/json; charset=utf-8" \
  -H "processingMode: auto" \
  -H "returnMoneyInMicros: false" \
  -H "skipReportHeader: true" \
  -H "skipReportSummary: true" \
  -d '{
    "params": {
      "SelectionCriteria": { "DateFrom": "2026-08-01", "DateTo": "2026-08-10" },
      "FieldNames": ["Date","CampaignId","CampaignName","Impressions","Clicks","Cost"],
      "ReportName": "my_report_20260811_120000",
      "ReportType": "CAMPAIGN_PERFORMANCE_REPORT",
      "DateRangeType": "CUSTOM_DATE",
      "Format": "TSV",
      "IncludeVAT": "YES"
    }
  }'
```

**Что означают коды ответа:**

| Код | Что делать |
|---|---|
| `200` | Отчёт готов, TSV прямо в теле ответа |
| `201` / `202` | Отчёт поставлен в очередь. Подождать столько секунд, сколько указано в заголовке ответа `retryIn`, и **повторить тот же самый запрос с теми же параметрами** |
| `400` | Ошибка в запросе, подробности в JSON-теле |
| `500` | Ошибка на стороне Яндекса, повторить позже |

Именно этот цикл «отправил → 202 → подождал → повторил» скрипт делает за вас.

**Что означают заголовки запроса:**

| Заголовок | Зачем |
|---|---|
| `Authorization: Bearer <токен>` | Обязателен |
| `Client-Login` | **Только для агентств** — логин клиента. Рекламодателю не нужен |
| `Accept-Language` | Язык названий и текстов ошибок: `ru`, `en`, `uk`, `tr` |
| `processingMode` | `online` (сразу, только для небольших отчётов), `offline` (в очередь), `auto` (сам выберет) |
| `returnMoneyInMicros: false` | **Ставьте обязательно.** Иначе деньги придут умноженными на 1 000 000 |
| `skipReportHeader: true` | Убрать служебную первую строку с названием отчёта |
| `skipReportSummary: true` | Убрать строку «Итого» в конце |

## Шаг 6. Автообновление по расписанию

Ежедневная выгрузка через cron. Важный момент: **перезапрашивать нужно не вчерашний день, а последние две недели** — Директ досчитывает статистику задним числом (см. [грабли](#грабли-о-которые-бьются-все)).

```bash
crontab -e
```

```cron
# каждый день в 6 утра — перезабрать последние 14 дней
0 6 * * * cd /path/to/direct && /usr/bin/python3 direct_stats.py --last-days 14 --out data/stats.csv >> logs/cron.log 2>&1
```

Скрипт перезаписывает файл целиком, поэтому «догнавшиеся» цифры за прошлые дни автоматически заменят старые.

## Справочник: типы отчётов и поля

### Типы отчётов (`--report-type`)

| Тип | Разрезка |
|---|---|
| `ACCOUNT_PERFORMANCE_REPORT` | По аккаунту целиком |
| `CAMPAIGN_PERFORMANCE_REPORT` | По кампаниям *(по умолчанию)* |
| `ADGROUP_PERFORMANCE_REPORT` | По группам объявлений |
| `AD_PERFORMANCE_REPORT` | По объявлениям |
| `CRITERIA_PERFORMANCE_REPORT` | По ключевым фразам и условиям показа |
| `SEARCH_QUERY_PERFORMANCE_REPORT` | По реальным поисковым запросам людей |
| `CUSTOM_REPORT` | Произвольный набор полей |
| `REACH_AND_FREQUENCY_PERFORMANCE_REPORT` | Охват и частота (медийка) |

### Часто нужные поля (`--fields`)

**Разрезы:** `Date`, `CampaignId`, `CampaignName`, `CampaignType`, `AdGroupId`, `AdGroupName`, `AdId`, `Criterion`, `CriterionId`, `Query`, `Device`, `Placement`, `AdNetworkType`, `RegionalId`, `Gender`, `Age`

**Метрики:** `Impressions`, `Clicks`, `Cost`, `Ctr`, `AvgCpc`, `AvgImpressionPosition`, `AvgClickPosition`, `Conversions`, `ConversionRate`, `CostPerConversion`, `Revenue`, `Sessions`, `BounceRate`, `AvgPageviews`

**Конверсии.** Поля `Conversions`, `ConversionRate`, `CostPerConversion`, `Revenue` требуют, чтобы к кампаниям был привязан счётчик Яндекс Метрики. Чтобы считать по конкретной цели — передайте `--goals 123456789` (можно несколько через запятую) и при желании модель атрибуции `--attribution LSC` (`LC`, `FC`, `LSC`, `LYDC`, `AUTO`).

### Периоды (`--date-range`)

Вместо явных дат можно указать: `TODAY`, `YESTERDAY`, `LAST_7_DAYS`, `LAST_30_DAYS`, `THIS_MONTH`, `LAST_MONTH`, `THIS_YEAR`, `ALL_TIME`, `AUTO`.

## Грабли, о которые бьются все

**1. `ReportName` должен быть уникальным.**
Если отправить запрос с уже использованным именем, но другими параметрами — придёт ошибка «отчёт с таким именем уже существует». Скрипт подмешивает в имя метку времени, поэтому проблемы не возникает. Если пишете свой код — делайте так же.

**2. Данные догоняются задним числом.**
Статистика за сегодня неполная. Дальше на цифры влияют: фильтрация невалидных кликов (скрутка), пересчёт НДС, корректировки. Правки прилетают в течение **нескольких дней**.
👉 Не выгружайте «только вчера». Каждый раз перезабирайте окно в 7–14 дней и перезаписывайте данные.

**3. Деньги в микроединицах.**
Без заголовка `returnMoneyInMicros: false` расход `1 234 560 000` — это 1234.56 ₽. Скрипт ставит `false` всегда.

**4. Баллы (units).**
Каждый запрос стоит баллов, суточный лимит зависит от оборота аккаунта. Остаток приходит в заголовке ответа `Units` в формате `потрачено/осталось/лимит` — скрипт печатает его после каждой выгрузки. Отчёты дешёвые, но если долбить API каждую минуту — лимит выберется.

**5. Агентствам обязателен `Client-Login`.**
Без него запрос уходит «в никуда» или отдаёт статистику не того аккаунта. Задайте `YANDEX_DIRECT_CLIENT_LOGIN` в `.env` или флаг `--client-login`.

**6. Разные срезы дают разные суммы.**
Отчёт по фразам не сойдётся с отчётом по кампаниям до копейки: часть показов не привязана к конкретной фразе (автотаргетинг, синонимы). Это не баг API.

**7. Одна заявка на одно приложение.**
Создавать по приложению на каждый рекламный аккаунт не нужно и вредно — заявки будут рассматриваться дольше.

## Таблица ошибок

| Симптом | Причина | Решение |
|---|---|---|
| `invalid_grant` при обмене кода | Код просрочен (>10 мин) или уже использован | Открыть ссылку авторизации заново, взять свежий код |
| `invalid_client` | Опечатка в `client_id` / `client_secret` | Перепроверить на странице приложения |
| `redirect_uri mismatch` | В приложении не прописан Redirect URI | Добавить `https://oauth.yandex.ru/verification_code` |
| Ошибка авторизации от API Директа | Токен протух, или не отмечено право `direct:api` | Перевыпустить токен, проверить права приложения |
| «Нет доступа к API» | Заявка из шага 2 не одобрена | Дождаться одобрения; пока — работать в песочнице |
| «Отчёт с таким именем уже существует» | Повтор `ReportName` с другими параметрами | Сделать имя уникальным |
| Расход выглядит как 9-значное число | Забыт `returnMoneyInMicros: false` | Добавить заголовок |
| Пустой отчёт при живых кампаниях | Не тот `Client-Login`, либо период вне дат открутки | Проверить логин и даты |
| Постоянные `202` без результата | Большой отчёт в очереди | Это нормально, ждать; сузить период или набор полей |

## Песочница

Работает **сразу**, не дожидаясь одобрения заявки. Полезна, чтобы отладить формат запросов.

```bash
YANDEX_DIRECT_SANDBOX=1 python direct_stats.py --date-from 2026-08-01 --date-to 2026-08-10
```

Адрес: `https://api-sandbox.direct.yandex.com/json/v5/`

Нюансы: данные там тестовые и не связаны с вашим боевым кабинетом; кампании в песочнице нужно предварительно создать через API. Для проверки «а правильно ли я формирую запрос» — годится, для «а сколько я потратил» — нет.
